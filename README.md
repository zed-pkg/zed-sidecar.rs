# zed-sidecar.rs

k8s sidecar for zed-pkg.

Inherits [`ores-otel-sidecar`](https://github.com/ores-otel/ores-otel-sidecar.rs).
Bind with `ZED_SIDECAR_BIND` (default `127.0.0.1:9090`).

```sh
cargo run --bin zed-sidecar
```

Env keys are centralized in `.cli-flags.toml` and generated by `f2e generate` into `generated/{rust,dart,typescript,gleam}`.

## Deployment probes

The [Kubernetes sidecar fragment](k8s/container.yaml) is intentionally
loopback-only; do not expose port 9090 through a Service. Its startup probe runs
`/zed-sidecar preflight` to validate the flags contract and immutable
`.ores-sidecar.toml` policy **without binding a listener**. This leaves the
existing `/zed-sidecar probe` liveness check responsible for testing the
running HTTP health listener, while allowing a bounded startup grace period.
Do not add a separate readiness probe: the sidecar is a probe helper, not a
service that gates application readiness.

The startup probe retries every 5 seconds for at most 12 failures. A persistent
preflight failure marks the container unhealthy and triggers Kubernetes
recovery instead of silently booting with invalid policy. Both checks execute
inside the container, so the health endpoint never needs to accept
non-loopback traffic.

Validate changes with `cargo test --locked` (including the real
`preflight` subprocess test and the checked-in Kubernetes probe contract).
